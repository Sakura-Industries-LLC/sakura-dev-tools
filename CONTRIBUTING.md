# Bug Reports & Contributions

This repository is maintained as a public, read-only distribution.
We do not host a public issue tracker, and we do not accept unsolicited pull requests or feature requests against this repository.

If you have found a bug or wish to propose a modification, you may do so via your own public fork:

1. **Fork this repository** to your own account.
2. **Create an isolated test case** that demonstrates the failure or the value of the proposed change.
3. **Commit your proposed fix or feature** so that the test case passes.
4. **Email a link to your fork** (including the specific commit hashes for the test and the fix/feature) to
   `submissions@sakuraindustries.net`.

The fork-and-email workflow is the filter, not a formality.
A proposal that arrives as a fork with a reproducer and a passing fix has demonstrated effort.
Drive-by pull requests, vague feature ideas, and "this would be nice" suggestions without a concrete change do not.

Sending a fork link is a proposal only.
It does not mean the work has been reviewed, accepted, or incorporated into this project.
If we decide to consider incorporating your work, we may contact you with next steps,
including any contributor terms that must be agreed before acceptance.

**Please note:** this is build tooling.
We are releasing it in the hope it proves useful, with no guarantees of acceptance of any submissions.
No proposal in this form should expect a timely response, or even a review.

This project is still evolving.
Public availability does not imply image-tag stability, configuration stability, or compatibility guarantees.
We may change base images, drop tools, restructure the Dockerfile layering, or break downstream forks without notice.

You are welcome to fork the project and adapt it for your own use case.
Forks are independent projects, and we do not guarantee compatibility with them.
